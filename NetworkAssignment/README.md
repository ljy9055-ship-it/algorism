# 게임 네트워크 프로그래밍 — 실행 안내

> 제출 묶음: Unity NGO 코인 게임(과제 A) + C# UDP 피어 통신(과제 B). 아래의 NGO 기능은 실제 실행 후 사용자 확인을 받았고, 일부 환경 정보와 정량 측정값은 제출 전에 추가 기입해야 합니다.

## 1. 개발 환경

| 항목 | 값 |
|---|---|
| 운영체제 | Windows (실습 화면 기준) |
| IDE | Visual Studio Code |
| .NET SDK | **제출 전 `dotnet --version` 출력값 기입** |
| Unity Editor | **6000.6.6f1** (제공된 Unity 실행 로그 기준) |
| NGO / Unity Transport 패키지 | **과제 A 구현 후 버전 기입** |

## 2. 프로젝트 위치

```text
NetworkAssignment/
├── gamenetwork/        # 과제 A: Unity 프로젝트 (실제 폴더명 확인 후 수정)
├── UdpPeer/            # 과제 B: C# 콘솔 프로젝트 (별도 준비)
├── README.md
├── DESIGN.md
└── TEST_REPORT.md
```

**주의:** 이 문서 세 개에는 실행 코드가 포함되지 않습니다. 실제 Unity 프로젝트와 `UdpPeer` 폴더를 같은 제출 묶음에 포함해야 합니다. Unity 프로젝트의 실제 폴더명은 제공된 실행 로그에서 `gamenetwork`로 보였으나 제출 전 직접 확인하세요. UDP에는 `.csproj`, `Program.cs`가 필요합니다. Unity에는 `Assets/`, `Packages/`, `ProjectSettings/` 등이 필요합니다. 빌드 실행 파일을 포함한다면 `.exe`뿐 아니라 `_Data` 폴더 등 빌드 구성 전체를 함께 포함하세요.

## 3. UDP 피어 실행

1. 터미널을 열고 `UdpPeer` 프로젝트 폴더로 이동합니다.
2. `dotnet run`을 실행하고 ID로 `A`를 입력합니다.
3. 다른 터미널에서도 같은 프로젝트를 `dotnet run`으로 실행하고 ID로 `B`를 입력합니다.
4. IP와 포트 입력 화면에서 Enter를 누르면 기본 설정이 사용됩니다.
5. 양쪽 모두 실행된 상태에서 이동 명령어를 입력하고 상대의 수신 표시를 확인합니다.

### 기본 통신 설정

| 피어 | 내 IP | 내 수신 포트 | 상대 IP | 상대 수신 포트 |
|---|---|---:|---|---:|
| A | `127.0.0.1` | 9001 | `127.0.0.1` | 9002 |
| B | `127.0.0.1` | 9002 | `127.0.0.1` | 9001 |

프로그램 시작 시 각각 **내 IP → 내 수신 포트 → 상대 IP → 상대 수신 포트**를 입력하여 설정을 변경할 수 있습니다. 동일 PC에서 A와 B를 각각 한 번씩 실행해야 합니다. 이미 사용 중인 포트에서 실행하면 `SocketException (10048)`이 발생할 수 있습니다.

### 조작 방법

| 입력 | 기능 |
|---|---|
| `W`, `A`, `S`, `D` | 자신의 Y+1, X-1, Y-1, X+1 이동 및 위치 메시지 전송 |
| `P` | 내 위치, 상대의 최신 위치·순서 번호, 누적 수신 통계 표시 |
| `T` | 저장된 이전 위치 메시지를 **그 번호와 좌표 그대로** 재전송 |
| `R` | 최신 위치 메시지를 **그 번호와 좌표 그대로** 재전송 |
| `E` | 빈 메시지·형식 오류·숫자 오류·알 수 없는 ID를 포함하는 시험 메시지 5개 송신 |
| `B` | 100개 또는 1,000개 새 위치 메시지 반복 전송 시험 |
| `Q` | 종료 |

`B` 시험은 각 메시지마다 X 좌표와 순서 번호를 증가시킵니다. 시험에 사용할 송신 간격은 현재 `Program.cs`의 `B` 반복문 안 `Task.Delay(...)` 줄로 정합니다. `await Task.Delay(10);`은 약 10ms 대기 조건, 해당 대기 줄 제거는 대기 없음 조건입니다. **현재 코드는 마지막 실습에서 대기 없음 조건으로 변경되었습니다.** 조건 변경 후 저장 및 프로그램 재실행이 필요합니다.

### 정상 실행 확인

- A와 B가 서로 다른 ID·포트로 실행됩니다.
- 예: A를 (3,5), B를 (8,2)로 이동시키면 A의 `P` 화면에 B의 (8,2), B의 `P` 화면에 A의 (3,5)가 보입니다.
- 같은 순서 번호를 다시 보내거나 이전 번호를 보내면 상대 위치에 다시 반영되지 않습니다.
- `E` 시험 후에도 프로그램이 계속 실행되며 정상 메시지를 받을 수 있습니다.
- `P`에서 전체 수신 데이터그램 / 정상 반영 / 오래된·중복 / 잘못된 메시지 수를 구분해 출력합니다.

### 시험 실행 시 주의

- 전송량 조건마다 **두 피어를 모두 재실행**하여 누적 통계를 초기화합니다.
- 상대 피어를 먼저 실행한 뒤 대량 전송합니다.
- 송신 성공은 수신 보장이 아닙니다. 송신 결과와 상대 측 `P` 출력을 **별도로** 기록합니다.
- 정상 반영 수는 전체 수신 데이터그램 수가 아닙니다. 순서가 뒤바뀌어 도착한 메시지는 수신되더라도 무시될 수 있습니다.
- 매우 짧은 `Task.Delay(1)`의 실제 지연 시간은 OS 타이머·스케줄링의 영향을 받으므로 정확히 1ms로 보장되지 않습니다.

## 4. NGO 코인 게임 실행 (구현·시험 확인)

### 환경과 게임 구성

- Unity Editor: **6000.6.6f1** (실행 로그에서 확인). NGO 및 Unity Transport의 **정확한 설치 버전은 제출 전** Unity `Window → Package Manager → In Project` 또는 `Packages/manifest.json`에서 확인하여 기입: NGO `________`, Unity Transport `________`.
- Unity 프로젝트: `gamenetwork/` (실제 폴더명 확인 후 경로 수정), 시작 씬: `CoinGameScene` (실제 씬 파일명 확인 후 수정).
- 게임은 같은 PC의 **Unity Editor = Host**, Windows 빌드 실행 파일 = **Client** 방식으로 확인했습니다.
- 기본 접속 주소 `127.0.0.1`, 포트 `7777`. 게임 시작 화면의 주소·포트 입력란에서 변경할 수 있습니다. Host와 Client는 같은 포트를 입력합니다.
- `Player` 프리팹은 `NetworkObject`, `CharacterController`, `PlayerMovement`, 소유자 권한 `NetworkTransform`(또는 이를 대신하는 `OwnerNetworkTransform`)을 사용합니다.
- 점수 정책: **공동 점수**. Client 재접속 때 점수와 남은 코인 상태는 Host가 보유한 값을 공유하며, 별도 개인 점수 복구는 구현하지 않았습니다.

### 빌드 및 실행 순서

1. Unity Hub에서 프로젝트를 열고 `CoinGameScene`을 엽니다. `File → Build Profiles`에서 Windows(x86_64)용 빌드에 씬이 포함되었는지 확인합니다.
2. 변경 사항을 저장하고 `Build`로 Windows 실행 파일을 만듭니다. 코드·프리팹 변경 뒤에는 빌드를 다시 해야 Editor와 빌드의 네트워크 컴포넌트 구성이 일치합니다.
3. Unity Editor에서 Play → **Host 시작**을 클릭합니다.
4. Windows 실행 파일을 별도로 실행하고 주소 `127.0.0.1`, 포트 `7777` → **Client 시작**을 클릭합니다.
5. 양쪽에서 두 플레이어 생성, 각자의 입력에 의한 이동, 공동 점수와 코인 상태 일치를 확인합니다.

### 조작과 시험 기능

| 조작 | 동작 | 기대하는 서버 판정/결과 |
|---|---|---|
| `W/A/S/D` | 본인 플레이어 이동 | 소유한 플레이어만 움직이며 상대 화면에도 동기화 |
| `E` | 가까운 미획득 코인 요청 | 서버가 ID·거리·획득 여부 확인 후 승인 시 점수 +1 |
| `F1` | 존재하지 않는 코인 ID `999` 요청 | `[거절] 잘못된 코인 ID` |
| `F2` | 미획득 코인 중 먼 코인 요청 | 서버의 거리 초과 판정 (충분히 먼 곳에서 실행) |
| `F3` | 이미 획득한 코인 요청 | `[거절] 이미 획득한 코인` |
| `F4` | 가까운 코인에 동일 플레이어의 요청 2회 전송 | 1회 지급, 이후 요청 거절 |
| `F5` | 코인 ID `0`에 대한 요청 | 두 플레이어가 같은 코인 ID를 연달아 요청하는 경쟁 시험 |
| `연결 종료` | 네트워크 연결 종료 | 종료 상태 표시; Host 없이 접속 시 실패 후 재시도 가능 |

F2 시험 전에는 멀리 있는 미획득 코인이 필요하고, F3 전에는 코인을 하나 획득해야 합니다. F5 시험 전에는 Host·Client 모두 코인 `0` 근처 서버 판정 거리(기본 2) 이내에 있어야 합니다. 시험 로그는 **Host의 Unity Console**에서 확인합니다. F5는 수동 연속 요청 시험으로, 동일 시각 도착을 입증하지 않습니다.

### 정상 상태와 재접속 확인

- 접속 UI에서 `Host 실행 중`, `Client 연결 성공`, 연결 종료·실패 상태와 입력 주소·포트를 확인합니다. 접속 중에는 중복 시작을 막으며, 연결 실패 시 다시 시도할 수 있습니다.
- 코인 획득 후 양쪽 화면에서 같은 코인이 숨겨지고 공동 점수가 동일하게 증가해야 합니다.
- 재접속 시험: 두 참여자가 코인 3개 획득 → Client 종료 → Host가 1개 더 획득 → Client 재접속. 두 화면 모두 **공동 점수 4**, **남은 코인 6개**로 일치하는지 확인했습니다.

## 5. 알려진 제한·환경 주의

- **NGO 이동은 소유자 권한 위치 동기화**입니다. 서버는 코인 획득 거리와 이미 획득했는지를 판정하지만, 악의적인 Client가 거짓 위치를 보내는 것까지 차단하는 서버 권한 이동 검증은 구현하지 않았습니다. 로컬 수업 규모용 시연입니다.
- NGO 코인 상태와 점수는 Host가 실행되는 동안 메모리에 유지됩니다. Host가 종료된 뒤 재실행하면 이전 게임 상태를 디스크에서 복구하지 않습니다.
- 코인 ID는 Inspector에서 `0`~`9`로 각각 고정해야 합니다. 중복 ID나 빠진 ID에 대한 자동 설정 검사는 미구현입니다.
- Unity의 `Edit → Project Settings → Player → Active Input Handling`은 **Both**로 설정해 레거시 `Input.GetAxisRaw`를 사용할 수 있게 했습니다.
- 과거 Editor와 빌드의 프리팹 버전이 달라 `NetworkBehaviour index ... out of bounds`가 발생했습니다. 동일한 프로젝트 상태로 **재빌드**해 해결했습니다.
- Unity URP 후처리 셰이더 관련 경고가 실행 로그에 나타난 적 있습니다. 게임 기능에 미치는 영향은 별도 계측하지 않았습니다.
- UDP 피어 재시작 후 이전 좌표·순서 번호 복구나 확정 전달/자동 재전송은 제공하지 않습니다(과제 필수 아님).
- UDP 수신 측 처리 시간은 따로 측정하지 않았습니다. 1ms 대기 조건은 약 16초로만 관찰됐으며 정확한 원본 숫자는 미확인입니다.
- **제출 전 기입:** .NET SDK 버전(`dotnet --version`), NGO/Unity Transport 패키지 버전, Unity 실제 프로젝트·씬 이름, 사용한 강의자료/코드의 상세 출처.
